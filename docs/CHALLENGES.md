## Fresh Windows verification: Ansible idempotence

The first Ubuntu pod run installed Docker packages, including systemd binaries. On the second run Ansible reported systemd as the service manager even though PID 1 in the disposable pod was not systemd; timezone management changed one extra item. The common role now checks /run/systemd/system before timezone management, and the Docker role uses the same runtime check. A fresh Ubuntu rerun recorded first changed=31, second changed=0, verify changed=0. Original records: docs/evidence/windows/ansible-run-initial.txt and ansible-run.txt. Lesson: installed binaries do not prove that a service manager is running.
